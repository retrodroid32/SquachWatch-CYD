# v1.21 Hardware Validation

This checklist is the physical release gate for the v1.21 detection-intelligence
work. CI already validates the full firmware board matrix, host tests and emulator
regression. The checks here cover behavior that still needs real radios, touch,
power states, NVS persistence and display hardware.

Do **not** tag or publish v1.21.0 until the required sections below have passed on
representative hardware.

## Hardware coverage

### Required representative hardware

These three classes cover the important hardware differences in v1.21:

- [ ] **3.2-inch CYD ST7798/ST7789-compatible** — `cyd32-st7798`
- [ ] **T-Watch S3** — `twatch-s3`
- [ ] **Classic 2.8-inch CYD** — `cyd` or `cyd-ili9341`

The 3.2-inch CYD exercises the custom shared display/touch bus profile. T-Watch
exercises ESP32-S3, capacitive touch, battery/sleep/wake behavior and haptics. A
classic CYD is the baseline shared-ESP32 path.

### Spot-check when hardware is available

These profiles are already required to compile in CI, but a physical smoke test is
still useful when the matching board is available:

- [ ] Freenove 3.2-inch — `freenove32`
- [ ] AWOK 2.4-inch — `awok`
- [ ] RL Phantom resistive — `rlphantom-r`

The fast display-clock variants are compile/release-profile coverage of the same
hardware and do not require a duplicate full functional pass unless a display issue
is being investigated:

- `cyd-fast`
- `cyd-ili9341-fast`
- `cyd32-st7798-fast`

`cyd35-fast` and `rlphantom` are not public release profiles and are not part
of the v1.21 release gate.

## 1. Upgrade and persistence

Run this at least once by upgrading from released v1.20.1 instead of starting from
a clean NVS image.

- [ ] Existing settings survive upgrade.
- [ ] Existing IGNORE entries migrate to Device Policies as **IGNORE**.
- [ ] Migrated entries still suppress normal interruption.
- [ ] Device Policies survive reboot.
- [ ] Alert Rules survive reboot.
- [ ] Existing BlackBox history still opens in LOG.
- [ ] Restored pre-v1.21 history does **not** claim evidence or RSSI history that
      was never stored.
- [ ] SD logging still uses the existing CSV format and continues appending.
- [ ] Security/duress wipe still removes SquachWatch logs and sensitive state.

## 2. Detection evidence

Exercise at least one real BLE signature path and one real Wi-Fi signature path.

- [ ] BLE detection records a concrete evidence source.
- [ ] Wi-Fi detection records a concrete evidence source.
- [ ] MORE INFO shows the evidence page before the generic explanation.
- [ ] BLE manufacturer/service/name evidence is displayed without corrupt text.
- [ ] Wi-Fi OUI/SSID evidence displays the actual matching value where available.
- [ ] AirTag/Find My and iBeacon evidence, when available, show the stronger exact
      payload evidence rather than only the generic Apple company ID.
- [ ] DEAUTH uses **hits** for frame count and **repeats** for qualifying bursts.

## 3. RSSI history and trend

Use a real transmitter that can be moved toward and away from the device.

- [ ] A fresh detection starts in **LEARNING**.
- [ ] Moving closer produces **APPROACHING** after enough samples.
- [ ] Holding position settles to **STEADY** without obvious oscillation.
- [ ] Moving away produces **MOVING AWAY**.
- [ ] ALERT sparkline updates while the alert is open.
- [ ] DEVICES LOG row shows the compact sparkline when there is room.
- [ ] Long names/types suppress the compact sparkline rather than overlapping text.
- [ ] Restored historical rows never draw a synthetic RSSI sparkline.

## 4. Per-type Alert Rules

Pick one common detection type and change only that type's rule.

- [ ] **LOG ONLY** still counts and logs the detection but does not interrupt.
- [ ] Confidence threshold rejects a lower-confidence match while leaving it logged.
- [ ] Repeat threshold works at 2, 3 and 5 sightings.
- [ ] One noisy DEAUTH burst does not incorrectly satisfy a multi-sighting rule.
- [ ] Cooldown suppresses a second fresh visit inside the selected interval.
- [ ] A fresh visit after cooldown can alert again.
- [ ] Per-type wake OFF prevents a normal signature alert from waking a sleeping
      display when the global wake setting would otherwise allow it.
- [ ] Defaults reproduce the old v1.20.1 behavior: alert ON, GLOBAL confidence,
      one sighting, cooldown OFF, wake ON.

### WATCH regression

WATCH must keep its pre-v1.21 meaning.

- [ ] WATCH still uses its dedicated WATCH alert path.
- [ ] WATCH bypasses AUTO SNOOZE.
- [ ] WATCH does **not** silently bypass ordinary per-type confidence/repeat/cooldown
      rules for normal signature alerts.

## 5. Device Policies

Use one device and cycle through every policy.

- [ ] **NORMAL** behaves according to its type's Alert Rule.
- [ ] **IGNORE** suppresses ordinary interruption but continues logging/counting.
- [ ] **TRUSTED** suppresses ordinary interruption but remains visibly distinct from
      IGNORE in Device Policies.
- [ ] **ALWAYS ALERT** bypasses per-type LOG ONLY, confidence, repeats, cooldown,
      device snooze and AUTO SNOOZE.
- [ ] ALWAYS ALERT does **not** resurrect a detection type disabled in DETECTION
      FILTER.
- [ ] ALWAYS ALERT does **not** override lock-screen alert security.
- [ ] Policies persist across reboot.
- [ ] Returning a device to NORMAL removes the persistent policy entry.

## 6. LOG DEVICES / EVENTS

- [ ] LOG opens in DEVICES view by default.
- [ ] DEVICES -> EVENTS selector works in landscape.
- [ ] DEVICES -> EVENTS selector works in portrait.
- [ ] EVENTS is newest-first chronological history.
- [ ] FIRST and BACK events are distinguishable.
- [ ] Event row shows time/uptime, type, MAC, RSSI, confidence and hit count.
- [ ] Name/vendor appears when available.
- [ ] HERE/GONE reflects the current live engine state.
- [ ] Current non-normal Device Policy appears where applicable.
- [ ] EVENTS rows are read-only; long-press WATCH/HUNT/IGNORE actions remain
      DEVICES-only.
- [ ] Switching repeatedly between DEVICES and EVENTS does not corrupt scroll state
      or crash.

## 7. T-Watch-specific checks

Required on `twatch-s3`.

- [ ] Battery sleep still blanks the display according to the configured timeout.
- [ ] Crown wake still works.
- [ ] A normal alert with wake enabled wakes the panel.
- [ ] A normal alert with per-type wake disabled leaves the sleeping panel dark.
- [ ] Haptic behavior still follows the existing global T-Watch buzz control.
- [ ] BLE LISTEN 25/50/75% still returns to the selected base duty after temporary
      SquachMesh invite boosting.
- [ ] SLEEP CPU 80/160/240 MHz still behaves normally.
- [ ] RADIO RESET and radio self-heal still work.
- [ ] Deep-sleep radio recovery still restores scanning.
- [ ] No recurrence of the ESP32-S3 deaf-radio condition during the test session.

## 8. 3.2-inch CYD-specific checks

Required on `cyd32-st7798`.

- [ ] Display orientation and colors are correct.
- [ ] Touch calibration and touch input remain correct.
- [ ] Shared LCD/touch SPI remains stable while LOG is rapidly switched between
      DEVICES and EVENTS.
- [ ] ALERT sparkline and LOG sparkline render cleanly without tearing or stale
      pixels.
- [ ] Backlight behavior remains correct.
- [ ] SD logging works while the new LOG/EVENTS UI is in use.

If the 80 MHz profile is used in production, add a short smoke pass with
`cyd32-st7798-fast` for display/touch stability.

## 9. General regression

Run on at least the 3.2-inch CYD and T-Watch.

- [ ] CLEAR/main screen remains responsive during active radio traffic.
- [ ] Full-screen alerts still dismiss and time out normally.
- [ ] Desk mode still shows detections correctly.
- [ ] Raw scan still opens and exits correctly.
- [ ] Detection Filter still enables/disables types correctly.
- [ ] AUTO SNOOZE still behaves normally.
- [ ] IGNORE/SNOOZE actions from existing UI paths still work.
- [ ] SquachMesh detect/transmit behavior is unchanged.
- [ ] OTA/update screens still open normally.
- [ ] No watchdog, panic, reset loop or unexpected reboot.
- [ ] Ten-second queue/frame/render diagnostics show no obvious regression under
      the same traffic used for the test.

## 10. Soak

For the final candidate:

- [ ] 3.2-inch CYD: at least one extended powered scan session with SD inserted.
- [ ] T-Watch: at least one battery session exercising sleep/wake and scanning.
- [ ] No unexplained reset, queue-drop growth, UI freeze or radio-deaf state.
- [ ] Reboot after the soak preserves Alert Rules and Device Policies.

creating the v1.21.0 tag.

`.github/release-notes/v1.21.0.md`, `VERSION=1.21.0`, full CI, and only then
