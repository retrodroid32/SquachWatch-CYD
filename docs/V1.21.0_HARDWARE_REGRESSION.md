# v1.21.0 Hardware Regression Checklist

**Status:** release gate for the feature-complete v1.21 detection-intelligence work  
**Public release remains:** v1.20.1 until this checklist is completed and reviewed

This checklist is for real-hardware validation after the automated firmware,
host-test and emulator gates are green. It is intentionally separate from the
release workflow: passing CI proves the code builds and the simulated behavior
is consistent; this document proves the integrated firmware behaves correctly
on actual boards.

## Required boards

The minimum v1.21 release gate is:

- [ ] 3.2" CYD / ESP32-2432S032R or E32R32P using `cyd32-st7798`
- [ ] LilyGo T-Watch S3 using `twatch-s3`

Recommended additional coverage when hardware is available:

- [ ] 2.8" CYD ST7789
- [ ] 2.8" CYD ILI9341
- [ ] Freenove 3.2"
- [ ] AWOK 2.4"
- [ ] RL Phantom 2.4" resistive
- [ ] 3.2" CYD 80 MHz display profile

The 3.5" ST7796 development profile and RL Phantom capacitive profile are not
release targets and are not part of this gate.

## 1. Clean boot and board basics

Run on each required board.

- [ ] Flash the exact candidate build for the selected board profile.
- [ ] Cold boot from power-off completes without reset loop, panic, watchdog,
      or crash card.
- [ ] Display orientation, colors and inversion are correct.
- [ ] Touch calibration completes or existing valid calibration loads.
- [ ] All soft buttons and Settings navigation respond correctly.
- [ ] Main SCAN screen renders without clipping or missing controls.
- [ ] LOG opens and returns normally.
- [ ] DESK opens and returns normally.
- [ ] Reboot preserves normal user settings.
- [ ] Serial ten-second diagnostics continue without new queue/drop anomalies.

### 3.2" CYD specifics

- [ ] 240x320 layout is correct in both supported orientations.
- [ ] XPT2046 touch stays aligned after reboot.
- [ ] Backlight control on GPIO27 behaves normally.
- [ ] Shared LCD/touch SPI operation remains stable during repeated navigation.
- [ ] If testing `cyd32-st7798-fast`, repeat touch/navigation stress at 80 MHz
      and confirm touch still runs correctly at its separate frequency.

### T-Watch S3 specifics

- [ ] Capacitive touch works after cold boot and wake.
- [ ] PMU/battery percentage and charging state are sane.
- [ ] Haptic alert behavior follows the existing global buzz setting.
- [ ] Screen sleep/wake still works.
- [ ] BLE LISTEN and SLEEP CPU settings still apply on battery.
- [ ] Radio self-heal / RADIO RESET still functions.
- [ ] No regression to the stock Arduino Wi-Fi-driver path.
- [ ] RTC/clock survives normal restart as expected.

## 2. Stage A — detection evidence and RSSI trend

Use at least one controllable BLE target and one controllable Wi-Fi target.

- [ ] A new detection shows the expected type.
- [ ] MORE INFO shows a concrete evidence source rather than UNKNOWN for a new
      live detection.
- [ ] BLE manufacturer/service/name evidence is correctly identified when that
      is the actual match path.
- [ ] Wi-Fi OUI or SSID evidence shows the actual matching source.
- [ ] AirTag/Find My and iBeacon evidence remain distinct when those targets are
      available.
- [ ] DEAUTH reports deauth evidence and does not treat every frame in one burst
      as a separate `repeats` sighting.
- [ ] RSSI history begins in LEARNING state.
- [ ] Moving the target closer produces APPROACHING after enough samples.
- [ ] Holding distance roughly constant produces STEADY.
- [ ] Moving the target away produces MOVING AWAY.
- [ ] ALERT sparkline updates while the alert is open.
- [ ] LOG direction/trend agrees with the observed movement.
- [ ] No obvious frame-rate or touch-response degradation during rapid sightings.

## 3. Stage B — per-type Alert Rules

Pick one detection type that can be triggered repeatedly.

### Default compatibility

- [ ] With untouched v1.21 settings, behavior matches v1.20.1: alerts enabled,
      GLOBAL confidence, one repeat, cooldown OFF, wake ON.

### LOG ONLY

- [ ] Set the type to LOG ONLY.
- [ ] Trigger the target.
- [ ] Detection is still counted.
- [ ] Detection appears in LOG/DEVICES.
- [ ] Detection appears in EVENTS.
- [ ] Full-screen alert does not interrupt.

### Confidence threshold

- [ ] Set a threshold above the target's actual signature confidence.
- [ ] Detection remains logged/counted but does not interrupt.
- [ ] Return to GLOBAL and confirm the global ALERT FILTER controls it again.

### Repeat threshold

- [ ] Set minimum repeats to 3.
- [ ] First and second sightings do not interrupt.
- [ ] Third qualifying sighting produces one alert.
- [ ] A single DEAUTH burst does not instantly satisfy a multi-sighting rule
      solely because it contains many frames.

### Cooldown

- [ ] Set a short cooldown (30 seconds is easiest to test).
- [ ] First fresh visit alerts.
- [ ] A second fresh visit inside cooldown does not interrupt.
- [ ] A fresh visit after cooldown alerts again.
- [ ] A continuously present device does not nag repeatedly just because the
      cooldown expires.

### Wake behavior

- [ ] With per-type wake ON and global wake behavior enabled, a normal signature
      alert wakes a sleeping display as expected.
- [ ] With per-type wake OFF, the same normal signature does not wake the screen.
- [ ] Logging/counting still occurs.

## 4. Stage C — Device Policies

Use one known device whose MAC remains stable during the test.

### IGNORE

- [ ] Set policy to IGNORE.
- [ ] Device still appears in LOG/DEVICES and EVENTS.
- [ ] Counts still change.
- [ ] Ordinary interruption is suppressed.
- [ ] Policy survives reboot.

### TRUSTED

- [ ] Set policy to TRUSTED.
- [ ] Device remains logged/counted.
- [ ] Ordinary interruption is suppressed.
- [ ] UI visibly distinguishes TRUSTED from IGNORE.
- [ ] Policy survives reboot.

### ALWAYS ALERT

- [ ] Set policy to ALWAYS ALERT.
- [ ] A fresh visit bypasses per-type LOG ONLY.
- [ ] A fresh visit bypasses confidence threshold.
- [ ] A fresh visit bypasses repeat threshold.
- [ ] A fresh visit bypasses per-type cooldown.
- [ ] A fresh visit bypasses device snooze / AUTO SNOOZE.
- [ ] The same visit does not produce a second duplicate alert later merely
      because the ordinary repeat threshold is crossed.

### Boundaries that ALWAYS ALERT must not bypass

- [ ] Disable the detection type in DETECTION FILTER; ALWAYS ALERT does not
      resurrect the discarded classification.
- [ ] With lock-screen alerts set to NONE, ALWAYS ALERT does not override that
      security choice.

### WATCH compatibility

- [ ] WATCH still takes its dedicated WATCH alert path.
- [ ] WATCH bypasses AUTO SNOOZE as before.
- [ ] WATCH does not become equivalent to ALWAYS ALERT for confidence, repeat,
      cooldown, or LOG ONLY rules.

## 5. Device-policy migration from v1.20.1

This is a release-critical migration test.

1. Flash released v1.20.1.
2. Add at least two devices to the old IGNORE list.
3. Power-cycle and confirm v1.20.1 still sees them.
4. Flash the v1.21 candidate without erasing NVS.

Then verify:

- [ ] Both old ignored devices appear as IGNORE policies.
- [ ] Their MAC/type information is intact.
- [ ] No unrelated settings are lost.
- [ ] A reboot after migration preserves the policies.
- [ ] Adding/changing/removing policies after migration persists normally.

If possible, repeat once from an older MAC-only ignore-list build to exercise
the pre-type `macs` migration path on real NVS.

## 6. Stage D — LOG DEVICES / EVENTS

### DEVICES

- [ ] DEVICES remains the default LOG view.
- [ ] One current row per device/type is shown as before.
- [ ] Long-press WATCH/HUNT/policy actions still work only from DEVICES.
- [ ] Scrolling and clear-log behavior are unchanged.

### EVENTS

- [ ] DEVICES / EVENTS selector switches reliably in landscape.
- [ ] Selector switches reliably in portrait.
- [ ] EVENTS is chronological, newest first.
- [ ] Repeated visits generate FIRST/BACK history as expected.
- [ ] Event rows show timestamp/uptime, type, full MAC, RSSI, confidence, hits,
      identity and current policy where applicable.
- [ ] HERE/GONE reflects current live state rather than being stored as stale
      historical data.
- [ ] Historical rows are view-only; long-press actions do not activate.
- [ ] Rebooted/restored BlackBox history remains readable.

## 7. Stage E — LOG RSSI sparkline

- [ ] Live DEVICES rows show the compact sparkline when horizontal room exists.
- [ ] Sparkline trend visually agrees with closer/steady/farther movement.
- [ ] Long type/name text takes priority; sparkline disappears instead of
      overlapping text.
- [ ] Timestamp remains readable.
- [ ] Portrait 240px layouts do not clip the row.
- [ ] Restored BlackBox rows do not fabricate a historical sparkline.

## 8. Persistence, BlackBox and SD regression

- [ ] Existing BlackBox history survives reboot.
- [ ] Restored historical rows explicitly avoid claiming evidence/RSSI history
      that was never persisted.
- [ ] New detections append to BlackBox normally.
- [ ] If microSD is present, CSV logging still works.
- [ ] Daily log rotation still works when trusted time is available.
- [ ] A security/duress wipe does not write buffered detections back afterward.
- [ ] No new NVS corruption, reset loop or lost settings after repeated policy
      and alert-rule changes.

## 9. Power, sleep and alert interaction

Run especially on T-Watch.

- [ ] Normal signature alert behavior is correct while awake.
- [ ] Normal signature alert behavior is correct while display is asleep.
- [ ] LOG ONLY detections do not cause unintended wake.
- [ ] Per-type wake OFF does not prevent logging/counting.
- [ ] ALWAYS ALERT obeys the intended wake path without bypassing lock security.
- [ ] AUTO SNOOZE still activates according to existing settings.
- [ ] WATCH remains exempt from AUTO SNOOZE only in its intended dedicated path.

## 10. Update-path regression

Do not create the public v1.21.0 tag for this test.

- [ ] USB/browser flash of the candidate works on each required board.
- [ ] Existing v1.20.1 -> candidate settings/NVS upgrade works without erase.
- [ ] UPDATE OVER WIFI still reaches this fork's GitHub Pages endpoint.
- [ ] If a signed lab candidate is available, OTA signature verification accepts
      the correct candidate and rejects an invalid/mismatched image.
- [ ] T-Watch update completes and radio/display recover after restart.
- [ ] 3.2" CYD update returns with correct display/touch profile.

## 11. Soak / repeated-interaction test

Minimum recommended run: 30-60 minutes per required board.

During the run:

- [ ] Trigger repeated BLE detections.
- [ ] Trigger repeated Wi-Fi detections.
- [ ] Switch DEVICES / EVENTS repeatedly.
- [ ] Open MORE INFO repeatedly.
- [ ] Change alert rules and policies.
- [ ] Enter/exit DESK and Settings.
- [ ] Exercise screen sleep/wake where supported.
- [ ] Watch serial queue/frame/render telemetry.

Pass criteria:

- [ ] No crash, watchdog, reset loop or UI lockup.
- [ ] No steadily increasing queue depth.
- [ ] No unexplained queue drops under normal test traffic.
- [ ] Touch remains responsive.
- [ ] SD logging, if enabled, remains healthy.
- [ ] Policies and rules still survive final reboot.

## Release exit criteria

v1.21.0 is ready for release preparation only when:

- [ ] Required 3.2" CYD test passes.
- [ ] Required T-Watch S3 test passes.
- [ ] v1.20.1 -> v1.21 policy migration passes on real NVS.
- [ ] Stage A-E feature tests pass on hardware.
- [ ] No release-blocking crash/reset/persistence issue remains open.
- [ ] Current master CI is green.
- [ ] Test results identify the exact master SHA that was exercised.

After these are satisfied, release preparation can proceed with a final
`.github/release-notes/v1.21.0.md`, `VERSION=1.21.0`, full CI, the matching
`v1.21.0` tag, OTA-key verification/signing, release artifact validation and
Pages publication.
